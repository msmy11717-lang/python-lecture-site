LECTURE 15

RAGとは何か

外部情報をLLMに渡す仕組み「RAG（Retrieval-Augmented Generation）」の概念と実装を学ぶ。社内情報・最新情報を扱えるAIの作り方。

RAGとは何か
RAGとは「Retrieval-Augmented Generation（検索拡張生成）」の略です。LLMが知らない情報（最新情報・社内ドキュメント・個人データなど）を、回答時に検索して渡すことで、正確な回答を可能にする仕組みです。第10回で「CSVをプロンプトに埋め込んでClaudeに分析させた」のも、シンプルなRAGです。
  • RAG = 検索（Retrieval）+ LLM生成（Generation）の組み合わせ
  • LLMを「頭脳」、外部データを「参考書」として使うイメージ
  • LLMのパラメータ（重み）は変えない。情報は毎回「渡す」だけ
  • 第10回のCSV分析・第6回のファイル読み込みがまさにRAGの基礎
なぜRAGが必要か
LLMは学習データが収集された時点の情報しか持っていません。また、あなたの会社の内部情報や個人ファイルはインターネット上に存在しないため、LLMは知ることができません。RAGはこの問題を解決します。
  • LLMの知識カットオフ以降の情報は知らない（例：昨日のニュース）
  • 社内マニュアル・契約書・会議メモは学習データに含まれない
  • 個人の予定・タスク・顧客情報も同様に知らない
  • RAGで「必要な情報をその都度渡す」ことでこれを解決する
RAGの基本フロー
フロー図（概念）
ユーザーの質問
    ↓
① 質問に関連する情報を検索・取得
   （ファイル読み込み / DB検索 / Web検索）
    ↓
② 取得した情報 ＋ 質問 をLLMに渡す
    ↓
③ LLMが情報を元に回答を生成
    ↓
回答
最も単純なRAG実装
RAGの本質は「ファイルを読んでプロンプトに入れる」だけです。高度なベクトル検索は必要ありません。まずはシンプルな実装から始めます。
python
import anthropic client = anthropic.Anthropic(api_key="sk-ant-ここに貼る") def ask_claude(prompt): response = client.messages.create( model="claude-haiku-4-5-20251001", max_tokens=800, messages=[{"role": "user", "content": prompt}] ) return response.content[0].text def simple_rag(question, knowledge_file): """シンプルRAG：ファイルを読んでプロンプトに埋め込む""" # ① 知識ベース（外部情報）を読み込む with open(knowledge_file, "r", encoding="utf-8") as f: knowledge = f.read() # ② 情報をプロンプトに埋め込んでLLMに渡す prompt = f"""以下の参考情報を元に、質問に答えてください。 参考情報に書かれていないことは「情報がありません」と答えてください。 【参考情報】 {knowledge} 【質問】 {question}""" # ③ LLMが情報を元に回答生成 return ask_claude(prompt) # 実行例 answer = simple_rag( question="営業部の連絡先を教えてください", knowledge_file="company_info.txt" ) print(answer)

複数ファイルに対応したRAG
python
import anthropic, os client = anthropic.Anthropic(api_key="sk-ant-ここに貼る") def multi_file_rag(question, knowledge_dir): """フォルダ内の全テキストファイルを知識ベースとして使うRAG""" # フォルダ内の全.txtファイルを読み込む knowledge_parts = [] for filename in os.listdir(knowledge_dir): if filename.endswith(".txt"): filepath = os.path.join(knowledge_dir, filename) with open(filepath, "r", encoding="utf-8") as f: content = f.read() knowledge_parts.append(f"=== {filename} ===\n{content}") all_knowledge = "\n\n".join(knowledge_parts) prompt = f"""以下のドキュメント群を参考に質問に答えてください。 {all_knowledge} 【質問】 {question}""" response = client.messages.create( model="claude-haiku-4-5-20251001", max_tokens=800, messages=[{"role": "user", "content": prompt}] ) return response.content[0].text # 使い方 # knowledge/ フォルダに company_info.txt, faq.txt, manual.txt を置く answer = multi_file_rag("有給休暇の申請方法を教えてください", "knowledge") print(answer)
RAGの限界と注意点
  • コンテキストウィンドウの上限：渡せる情報量に限りがある（数万〜数十万トークン）
  • 情報が多すぎると重要な部分が埋もれる → 関連部分だけを絞って渡す工夫が必要
  • 情報の品質がそのまま回答品質に影響する → ゴミを渡すとゴミが返る
  • 最新情報を渡しても、LLM自体の限界（ハルシネーション）は残る → 第16回で詳述
