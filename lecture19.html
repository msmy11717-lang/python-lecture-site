LECTURE 19

Gitの基本操作

git init・git add・git commit・git log の4コマンドを実際に動かす。ワーキングディレクトリからリポジトリへの流れとコミットIDの概念を習得する。

4つの基本コマンド
Gitの日常操作は4つのコマンドがベースです。この4つを覚えれば「変更履歴の管理」という最重要機能を使えます。
  • git init → フォルダをGit管理下に置く（最初の1回だけ）
  • git add ファイル名 → ステージングエリアにファイルを追加する
  • git commit -m "メッセージ" → ステージングの内容をリポジトリに保存する
  • git log → コミット履歴（セーブポイント一覧）を確認する
ワーキングディレクトリ→ステージング→リポジトリの流れ
ターミナル（Git操作の基本フロー）
# ① フォルダをGit管理下に置く（最初の1回）
git init

# ② ファイルを作って編集する（ワーキングディレクトリで作業）
echo "# メモ" > note.txt

# ③ ステージングエリアに追加する
git add note.txt
# すべてのファイルをまとめて追加する場合
git add .

# ④ コミット（セーブポイントを打つ）
git commit -m "最初のメモを追加"

# ⑤ 履歴を確認する
git log
git log の出力を読む
git log の出力例
commit e697081a3f2c1b9d4e8f0a1c2b3d4e5f6a7b8c9d  ← コミットID（ハッシュ）
Author: 田中誠 <tanaka@example.com>
Date:   Sat May 17 10:30:00 2025 +0900

    最初のメモを追加  ← コミットメッセージ

commit 6d4aaf6b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6
Author: 田中誠 <tanaka@example.com>
Date:   Fri May 16 09:15:00 2025 +0900

    プロジェクト初期化
コンパクトに一覧表示したいときは git log --oneline を使います。
コミットID（ハッシュ）の概念
各コミットには「e697081a...」のような40文字の一意なIDが自動生成されます。これをコミットIDまたはハッシュと呼びます。
  • コミットIDはSHA-1アルゴリズムで自動生成される（世界中で重複しない）
  • 最初の7文字だけでも識別できる（git log --oneline で短縮表示）
  • このIDを使って「特定のコミット時点に戻る」操作が可能（git checkout ハッシュ）
  • コミットIDはGitが自動で付けるため、自分で決める必要はない
確認課題
✓ この講義の課題
  • 任意のフォルダで git init を実行し、.git フォルダが生成されることを確認する
  • テキストファイルを作成して git add → git commit の流れを実際に行う
  • git log --oneline でコミットIDの先頭7文字が表示されることを確認する
  • 2回目のコミットを行い、git log で2つのコミットが記録されていることを確認する
