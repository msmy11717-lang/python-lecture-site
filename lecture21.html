LECTURE 21

GitHubとは何か

GitのリポジトリをクラウドにホストするGitHubを理解する。ローカルとリモートの関係、git remote add・git push・git pull の概念と、バックアップ・共有・公開の3用途を習得する。

GitHubはGitのリポジトリをクラウドに置く場所
Gitはあなたのパソコン（ローカル）上だけで動くツールです。GitHubはそのリポジトリをインターネット上（クラウド）に置いて、バックアップ・共有・公開を可能にするサービスです。
  • Git = バージョン管理の仕組み（ローカルで完結）
  • GitHub = Gitリポジトリを置くクラウドサービス（Microsoft傘下）
  • GitとGitHubは別物。GitなしでGitHubは使えないが、GitHubなしでGitは使える
  • 類似サービス：GitLab・Bitbucket（どれもGitをベースにしている）
ローカルとリモートの関係
ローカルとリモートの概念図
【ローカル（自分のPC）】          【リモート（GitHub）】
  ワーキングディレクトリ
       ↓ git add
  ステージングエリア
       ↓ git commit
  ローカルリポジトリ    →  git push  →  リモートリポジトリ
                       ←  git pull  ←  （GitHubのサーバー上）

  ※ push：ローカルの変更をリモートに送る
  ※ pull：リモートの変更をローカルに取得する
git remote add・git push・git pull の操作
ターミナル（リモート連携の基本コマンド）
# ① ローカルリポジトリにリモートを登録する（最初の1回）
git remote add origin https://github.com/ユーザー名/リポジトリ名.git

# リモートが正しく登録されているか確認
git remote -v

# ② ローカルの変更をGitHubに送る（プッシュ）
git push origin main

# ③ GitHubの変更をローカルに取得する（プル）
git pull origin main

# ④ GitHubからリポジトリごとコピーする（クローン）
git clone https://github.com/ユーザー名/リポジトリ名.git
バックアップ・共有・公開の3用途
  • ① バックアップ：パソコンが壊れてもGitHubにpushしてあれば全履歴ごと復元できる
  • ② 共有：チームメンバーが同じリポジトリをcloneして共同開発できる（pull/pushで同期）
  • ③ 公開：リポジトリをPublicにすれば世界中に公開できる（ポートフォリオとして活用可能）
  • Private リポジトリ：自分だけが見える非公開設定（デフォルト）
確認課題
✓ この講義の課題
  • github.com でアカウントを作成する（まだない場合）
  • GitHubで新しいリポジトリを作成する（New Repository）
  • git remote add origin でローカルとリモートを接続する
  • git push でローカルのコミットをGitHubにアップロードして確認する
