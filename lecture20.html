LECTURE 20

ブランチとは何か

作業の分岐点「ブランチ」の概念を理解する。master（本線）とfeature（試作線）の関係、git branch・git checkout -b・git merge の操作を習得する。

ブランチ＝作業の分岐点
ブランチとは「コミット履歴の分岐点」です。本線（master/main）から分岐した「試作線」を作ることで、本番に影響を与えずに新機能を試せます。
ブランチの概念図
main（本線）
  ○──○──○──────────────○  ← 本番コード（常に動く状態を保つ）
           \           /
            ○──○──○        ← feature（試作線）で新機能を開発
                            ← 完成したら main に merge（合流）
  • main / master ブランチ：本番コード（常に正常に動く状態を維持する）
  • feature ブランチ：新機能・試作品を作る専用の作業線
  • ブランチを切ると、main の状態を保ったまま自由に変更を加えられる
  • マージ（merge）で feature の変更を main に取り込む
ブランチの基本操作
ターミナル（ブランチ操作）
# 現在のブランチを確認する（* が現在地）
git branch

# 新しいブランチを作って、そこに移動する（-b で作成+移動）
git checkout -b feature/new-function

# ブランチを切り替える（既存のブランチへ移動）
git checkout main

# feature ブランチで作業してコミット
git add .
git commit -m "新機能を追加"

# main ブランチに戻ってマージ
git checkout main
git merge feature/new-function

# マージ済みのブランチを削除（不要になったら）
git branch -d feature/new-function
マージの概念
マージとは「feature ブランチで加えた変更を main ブランチに取り込む操作」です。2つの分岐した歴史を1つに合流させます。
  • Fast-forward マージ：mainに変更がない場合、そのまま先に進める（単純な合流）
  • コンフリクト（競合）：2つのブランチで同じ行を変更した場合に発生する → 手動で解決
  • ブランチ名の慣習：feature/〇〇（新機能）・bugfix/〇〇（バグ修正）・hotfix/〇〇（緊急修正）
  • Claude Codeもブランチを自動で作成・マージする操作が可能
確認課題
✓ この講義の課題
  • git checkout -b feature/test で新しいブランチを作成し、git branch で確認する
  • feature ブランチでファイルを追加してコミットする
  • main ブランチに戻り、git merge feature/test でマージする
  • git log --oneline でマージコミットが記録されていることを確認する
