LECTURE 13

プロンプトは何をしているのか

3層構造（System・User・Assistant）と確率の地図という概念で、プロンプトの本質的な役割を理解する。

プロンプトの正体
プロンプトは「LLMへの指示文」ではなく、「確率空間上の出発点を決めるもの」です。第12回で学んだように、LLMは確率的に次のトークンを選びます。プロンプトはその確率分布を大きく変えます。同じLLMでも、プロンプト次第で全く異なる回答が返ります。
  • プロンプト = LLMが次のトークンを選ぶための「文脈・出発点」
  • 文脈が変わると確率分布が変わり、回答が変わる
  • 「プロンプトエンジニアリング」とは確率空間を狙い通りに絞り込む技術
  • モデルを変えなくてもプロンプトで劇的に出力品質が変わる
3層構造：System / User / Assistant
Claude APIでは3種類のメッセージロールがあります。それぞれ役割が異なり、組み合わせることで高度な制御ができます。
python
import anthropic

client = anthropic.Anthropic(api_key="sk-ant-ここに貼る")

response = client.messages.create(
    model="claude-haiku-4-5-20251001",
    max_tokens=500,

    # ① Systemプロンプト：AIの人格・役割・制約を定義する
    system="あなたは経験豊富なPythonコーチです。初心者に対して、"
           "専門用語を避けシンプルな言葉で丁寧に説明してください。"
           "回答は必ず3行以内にまとめてください。",

    # ② Userメッセージ：ユーザーからの質問・指示
    messages=[
        {"role": "user", "content": "関数とは何ですか？"}
    ]
)

print(response.content[0].text)
  • system → AIの「人格・役割・行動ルール」を設定する（会話全体に影響）
  • user → ユーザーの発言・質問・指示
  • assistant → AIの返答（Few-shotで事前に例を入れられる）
  • systemは1つだけ。user/assistantは交互に複数追加できる
Few-shotプロンプティング
Few-shotとは「例を数件見せることで、LLMに出力形式を学習させる」技術です。formatを文章で説明するより、例を示す方が精度が上がります。
python
import anthropic client = anthropic.Anthropic(api_key="sk-ant-ここに貼る") # Few-shot：入力→出力の例を会話形式で先に見せる response = client.messages.create( model="claude-haiku-4-5-20251001", max_tokens=200, system="商品レビューを「良い/普通/悪い」の3段階で分類してください。", messages=[ # 例1（Few-shot） {"role": "user", "content": "レビュー：品質が素晴らしく大満足です"}, {"role": "assistant", "content": "良い"}, # 例2（Few-shot） {"role": "user", "content": "レビュー：普通の商品でした"}, {"role": "assistant", "content": "普通"}, # 本番の質問 {"role": "user", "content": "レビュー：壊れやすくてがっかりしました"} ] ) print(response.content[0].text) # → "悪い"
プロンプトが確率空間を絞り込む仕組み
「Pythonとは？」という質問だけでは、LLMは無数の回答候補を持ちます。Systemプロンプトで「初心者向け・3行以内」と制約すると、確率分布が絞られ、狙い通りの回答が出やすくなります。
  • 制約なし → 広い確率分布（回答がブレる）
  • 役割定義あり → 特定ドメインに確率が集中（専門家風の回答）
  • 出力形式指定 → 形式の確率が最大化（箇条書き・JSON・3行など）
  • 例示（Few-shot） → 例と同じパターンに確率が収束
実用的なプロンプト設計の原則
  • ① 役割を明示する：「あなたは〇〇の専門家です」
  • ② 出力形式を指定する：「箇条書き3つで」「JSON形式で」
  • ③ 制約を与える：「200文字以内」「専門用語を使わず」
  • ④ 例を見せる（Few-shot）：形式の一貫性が上がる
  • ⑤ コンテキストを渡す：背景情報をSystemやUserに含める（→ RAG：第15回）
確認課題
✓ この講義の課題
  • System・User・Assistantの3層を使ったプロンプトを自分で設計してAPIで送信する
  • Few-shotで出力形式（JSON・箇条書きなど）を固定するコードを書いて動作確認する
  • 同じUserメッセージに対してSystemプロンプトあり・なしで回答を比較する
