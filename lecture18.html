LECTURE 18

Gitとは何か

バージョン管理の概念を理解する。Gitが「何を解決するのか」「どこにデータを置くのか」「コミットとは何か」を整理する。

Gitが解決する問題
ファイルを手動で管理すると「report_最終版.docx」「report_最終版2.docx」「report_本当に最終版.docx」のような混乱が起きます。Gitはこの問題を解決する「変更履歴の管理システム」です。
  • いつ・何を・なぜ変えたかを記録できる
  • 過去の任意の状態に戻れる（Ctrl+Zの無限版）
  • 複数人が同じファイルを同時に編集しても競合を管理できる
  • 「最終版」ファイルを大量に作る必要がなくなる
Gitの3つの場所
Gitはファイルを「3つの場所」で管理します。この3つの場所の概念がGitを理解する上で最も重要なポイントです。
Gitの3つの場所（概念図）
【ワーキングディレクトリ】
  あなたが実際に編集しているファイルが置かれる場所
  例：script.py を書いて保存している状態
         ↓ git add
【ステージングエリア】
  「次のコミットに含めるファイル」を一時的に置く場所
  コミットする前に「何をセーブするか」を選ぶステージ
         ↓ git commit
【リポジトリ（.git フォルダ）】
  コミット（セーブポイント）が永久保存される場所
  git log で全履歴を確認できる
  • ワーキングディレクトリ：今作業しているフォルダ（普通のファイル）
  • ステージングエリア：「次に保存するもの」の選択エリア（git add で移動）
  • リポジトリ：全履歴が入った .git フォルダ（git commit で確定）
コミットとは「セーブポイントを打つ」行為
ゲームのセーブポイントと同じイメージです。コミットを打つと「その時点の全ファイルの状態」がリポジトリに永久保存されます。あとでいつでもその時点に戻れます。
  • コミット = セーブポイント（その瞬間のスナップショット）
  • 各コミットには「コミットメッセージ」（変更理由）を書く
  • コミットID（ハッシュ）という一意の番号で管理される
  • コミットを積み重ねるほど、過去の好きな時点に戻れる
